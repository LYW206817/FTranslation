## v174 — BaoCode 远端 server 与服务器 DNS（2026-11-18）

BaoCode 升级到 `2.0.2+35` 后连不上 `100.x` 地址，报 `The BaoCode server for Linux x64 could not be downloaded`。Qoder 与 Codex 同时正常，说明 SSH 与 Tailscale 通道本身没问题。

根因：BaoCode 需要与客户端版本匹配的 `baocode-server`。本机 `remote/servers.json` 声明版本 `2.0.2.35-d0c299e2b113`，下载地址为 `https://dl.baocode.dev/releases/remote/2.0.2.35-d0c299e2b113/baocode-server-linux-x64.gz`（4.5 MB）；服务器上最新只有 `2.0.1.34`。服务器 `getent hosts dl.baocode.dev` 无结果，`curl` 9.7 秒后返回 HTTP 000。`resolvectl status` 显示 eth0 使用阿里云内网 DNS `100.100.2.136` / `100.100.2.138`，而公共 DNS `223.5.5.5` 能解析到 Cloudflare 的 `172.67.170.211` / `104.21.28.133`，说明域名可达、问题在本地解析器。

处理：

- 本机下载 gz，校验 `sha256` 与 `servers.json` 一致（`25748016…3c4b`），scp 上传后解压到 `/root/.baocode-server/2.0.2.35-d0c299e2b113/baocode-server`（755）。
- 服务器新增 `/etc/systemd/resolved.conf.d/99-ft-dns.conf`：`DNS=223.5.5.5 119.29.29.29`、`FallbackDNS=1.1.1.1 8.8.8.8`，重启 `systemd-resolved`。

### 验证

- `resolvectl query dl.baocode.dev` 返回 4 条 A/AAAA 记录；对下载 URL 的 HEAD 请求 HTTP 200、0.95 s（改前 HTTP 000、9.7 s 失败）。
- `resolvectl query ftranslation.cn` 22 ms 返回 `114.55.166.224`；`fasttranslation`、`caddy`、`tailscaled` 均 active；`https://ftranslation.cn/health` 返回 HTTP 200。

### 残留风险

- 手工放置的 server 目录不在 `servers.json` 的自动管理路径里；BaoCode 下次升级应能自动下载，但未实测。
- 公共 DNS 与内网 DNS 并存，若某些阿里云内部域名依赖 `100.100.2.136` 的特殊解析，尚未实测。
