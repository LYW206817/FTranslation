## v141 停售年付，改卖季付；按 88 万字符 10 元标价打 6.9 / 5.6 / 4.5 折

### 为什么

参考图用「划线价 + 折扣」做价格锚点。原先的年付 69 / 119 / 199 是「12 个月收 10 个月」（8.3 折），与后来确认的口径不一致：用户要的是「88 万字符 10 元」的标价，Lite 卖 6.9 元就是 6.9 折；同时年付承诺太长，改为季付。季付不额外打折，按 3 倍月价收（20.7 / 35.7 / 59.7），所以三档相对标价仍是 6.9 / 5.6 / 4.5 折。

### 改了什么

- `server/FastTranslation.Server/Orders/OrderPricing.cs`：`yearly` / 365 天换成 `quarterly` / 90 天，价格 2,070 / 3,570 / 5,970 分；历史 `yearly` 订单仍按库里的 `days` 开通，新单不再接受 `yearly`。
- `src/FastTranslation.App/Pages/PlanPage.xaml`：月付 / 年付分段控件改为月付 / 季付（90 天）；卡片第二行改成「季付 ¥20.7 · 标价 ~~¥30~~」+「6.9 折」徽标，Pro / Max 分别是 35.7 / ~~64.1~~ / 5.6 折与 59.7 / ~~132.3~~ / 4.5 折。划线价是 3 个月的标价（88 万字符 10 元线性折算），不是历史成交价。
- `src/FastTranslation.App/Pages/PlanPage.xaml.cs` / `src/FastTranslation.Core/Account/AccountTypes.cs` / `admin/admin.js`：周期值改 `quarterly`，订单摘要显示「季付」；`yearly` 只保留给历史订单展示。
- `site/index.html`：三张卡的年付行改成季付 20.7 / 35.7 / 59.7，并补一句「标价按 88 万字符 10 元折算，月付 / 季付同单价」。
- `docs/superpowers/specs/2026-10-28-account-and-billing-design.md`：D7、§6.1、§6.3 与剩余待定同步改为季付。
- 测试：服务端下单 / 续费断言改 90 天、3,570 分；客户端订单映射断言 `quarterly → 季付`、`¥35.70`。

### 验证

```
dotnet build FastTranslation.slnx -c Release → 0 警告 0 错误
dotnet test（Debug）→ Core 452 / Platform.Windows 109 / Providers 101 / Server 322 = 984 全绿
dotnet test -c Release --no-build → 同上 984 全绿
```

- 首次 Debug 全量跑时 `QwenMtImageTranslatorTests.RateLimitedTwice_ReturnsRateLimitedWithoutThirdTry` 因共享 `HttpListener` 被释放偶发失败一次；单独重跑 provider 项目 101 全绿，再跑全量也全绿。与本次改动无关。
- 截图：`assets/qa/plan-v141-pricing.png`（从 `plan-v141.png` 裁出套餐卡区域，避开账号邮箱与用量数字）——三张卡都显示季付总价、划线标价与折扣徽标，右上角为「月付 30 天 / 季付 90 天」。
- 站点截图：`assets/qa/site-plans-before.png` / `site-plans-after.png`（headless Chrome 1400×900，取 `#plans`）——三张卡的年付行换成季付行，栏目说明补了「标价按 88 万字符 10 元折算」与「季付一次付 90 天」。
- 交付重启：`tools/qa/shot-plan-v141.ps1` 启动 Release 产物并保持运行，主窗口标题 `Fast Translation`。

### 残留风险与未验证项

- 季付与月付同单价；如果以后要给季付额外折扣，必须同时改 `OrderPricing.PricesCents`、卡片文案、站点与规格，并重新计算徽标（现在的 6.9 / 5.6 / 4.5 折只对「3 倍月价」成立）。
- 划线价是标价锚点，不是历史成交价；对外文案不要写「原价」或暗示曾经按该价卖过。
- 历史 `yearly` 订单仍可确认并按 365 天开通，后台能显示「年付」；这是刻意保留的兼容路径，不代表重新开卖年付。
- 客户端分段控件没有单独的自动化测试（WPF 交互），季付选中态靠截图证据；服务端 90 天与金额有测试覆盖。

## v142 套餐卡视觉重做：季付价格联动与 Hot 徽标

### 为什么

v141 只改了订单周期，卡片的大价格仍固定月价；用户切到季付后，大价格还是 ¥6.9/月，必须自己乘 3 才知道要付 20.7。用户同时指出「推荐」蓝徽标和折扣徽标挤在第二行，层级不清。这一版把大价格与周期联动，把推荐改成火红 Hot，把折扣移到档位名后，并整体上调字号。

### 改了什么

- `src/FastTranslation.App/Pages/PlanPage.xaml`：三张卡的档位名 18px、价格 38px、权益 13px、说明 12.5px；折扣徽标从第二行移到档位名后，字号 11.5；Pro 的「推荐」改成 `Hot`，底色用主题 `DangerBrush`（浅色 #DC2626 / 深色 #FF6B6B），文字用 `OnBrandTextBrush`，两套主题都保持对比度。
- `src/FastTranslation.App/Pages/PlanPage.xaml.cs`：加 `PriceCopy` 记录三档四价（月价、季价、月标价、季标价）；`SelectCycle` 调 `UpdatePrices`，月付显示 ¥6.9/月、季付显示 ¥20.7/季，副行回显另一周期与划线标价。
- 周期卡补 `AutomationProperties.Name` / `AutomationId`，UIA 探针能按名字定位；选中态仍靠边框和底色。
- `site/index.html` / `site/assets/site.css`：Pro 的「推荐」标签同步改成 `Hot`，新增 `--hot: #D92D20`。
- 没有改价格、订单金额或服务端逻辑。

### 验证

```
dotnet build FastTranslation.slnx -c Release → 0 警告 0 错误
dotnet test（Debug）→ Core 452 / Platform.Windows 109 / Providers 101 / Server 322 = 984 全绿
dotnet test -c Release --no-build → 同上 984 全绿
```

- 截图：`assets/qa/plan-v141-pricing.png`（月付）与 `plan-v141-pricing-quarterly.png`（季付），用 `PrintWindow` 抓窗口，避开桌面挂件；再裁到套餐卡区域，避开账号邮箱与用量数字。月付大价格 ¥6.9/月，季付切到 ¥20.7/季，三档同步；Hot 红徽标在 Pro 右上角，折扣徽标在档位名后。
- 站点截图：`assets/qa/site-plans-before.png` / `site-plans-after.png`（headless Chrome 1400×900，取 `#plans`），Pro 标签由蓝色「推荐」改为火红 Hot。
- 交付重启：Release 产物保持运行，主窗口 `Fast Translation`。

### 残留风险与未验证项

- 价格文案现在有 XAML 初始值、`PriceCopy` 表、服务端 `OrderPricing.PricesCents` 三处；改价必须同批改，否则切换周期会露馅。
- Hot 借用了 `DangerBrush`（语义上是错误色）；如果以后要独立的品牌红，需要给 `ThemeColors` 加 `Hot` 令牌，并同步浅/深色两套值。
- WPF 周期切换没有 xunit 覆盖，只有截图；`ApplyPrice` 的 Inlines 重建逻辑也依赖 UI 线程，未做单元测试。
