## v141 停售年付，改卖季付；按 88 万字符 10 元标价打 6.9 / 5.6 / 4.5 折

### 为什么

参考图用「划线价 + 折扣」做价格锚点。原先的年付 69 / 119 / 199 是「12 个月收 10 个月」（8.3 折），与后来确认的口径不一致：用户要的是「88 万字符 10 元」的标价，Lite 卖 6.9 元就是 6.9 折；同时年付承诺太长，改为季付。季付不额外打折，按 3 倍月价收（20.7 / 35.7 / 59.7），所以三档相对标价仍是 6.9 / 5.6 / 4.5 折。

### 改了什么

- `server/FastTranslation.Server/Orders/OrderPricing.cs`：`yearly` / 365 天换成 `quarterly` / 90 天，价格 2,070 / 3,570 / 5,970 分；历史 `yearly` 订单仍按库里的 `days` 开通，新单不再接受 `yearly`。
- `src/FastTranslation.App/Pages/PlanPage.xaml`：月付 / 年付分段控件改为月付 / 季付（90 天）；卡片第二行改成「季付 ¥20.7 · 标价 ~~¥30~~」+「6.9 折」徽标，Pro / Max 分别是 35.7 / ~~64.1~~ / 5.6 折与 59.7 / ~~132.3~~ / 4.5 折。划线价是 3 个月的标价（88 万字符 10 元线性折算），不是历史成交价。
- `src/FastTranslation.App/Pages/PlanPage.xaml.cs` / `src/FastTranslation.Core/Account/AccountTypes.cs` / `admin/admin.js`：周期值改 `quarterly`，订单摘要显示「季付」；`yearly` 只保留给历史订单展示。
- `site/index.html`：三张卡的年付行改成季付 20.7 / 35.7 / 59.7，并补一句「标价按 88 万字符 10 元折算，月付 / 季付同单价」。
- `docs/superpowers/specs/2026-10-28-account-and-billing-design.md`：D7、§6.1、§6.3 与剩余待定同步改为季付。
- 测试：服务端下单 / 续费断言改 90 天、3,570 分；客户端订单映射断言 `quarterly → 季付`、`¥35.70`。

```

dotnet test（Debug）→ Core 452 / Platform.Windows 109 / Providers 101 / Server 322 = 984 全绿
dotnet test -c Release --no-build → 同上 984 全绿
```

- 首次 Debug 全量跑时 `QwenMtImageTranslatorTests.RateLimitedTwice_ReturnsRateLimitedWithoutThirdTry` 因共享 `HttpListener` 被释放偶发失败一次；单独重跑 provider 项目 101 全绿，再跑全量也全绿。与本次改动无关。
- 截图：`assets/qa/plan-v141-pricing.png`（从 `plan-v141.png` 裁出套餐卡区域，避开账号邮箱与用量数字）——三张卡都显示季付总价、划线标价与折扣徽标，右上角为「月付 30 天 / 季付 90 天」。
- 站点截图：`assets/qa/site-plans-before.png` / `site-plans-after.png`（headless Chrome 1400×900，取 `#plans`）——三张卡的年付行换成季付行，栏目说明补了「标价按 88 万字符 10 元折算」与「季付一次付 90 天」。

### 残留风险与未验证项

- 季付与月付同单价；如果以后要给季付额外折扣，必须同时改 `OrderPricing.PricesCents`、卡片文案、站点与规格，并重新计算徽标（现在的 6.9 / 5.6 / 4.5 折只对「3 倍月价」成立）。
- 划线价是标价锚点，不是历史成交价；对外文案不要写「原价」或暗示曾经按该价卖过。
- 历史 `yearly` 订单仍可确认并按 365 天开通，后台能显示「年付」；这是刻意保留的兼容路径，不代表重新开卖年付。
- 客户端分段控件没有单独的自动化测试（WPF 交互），季付选中态靠截图证据；服务端 90 天与金额有测试覆盖。

## v142 套餐卡视觉重做：季付价格联动与 Hot 徽标

### 为什么

v141 只改了订单周期，卡片的大价格仍固定月价；用户切到季付后，大价格还是 ¥6.9/月，必须自己乘 3 才知道要付 20.7。用户同时指出「推荐」蓝徽标和折扣徽标挤在第二行，层级不清。这一版把大价格与周期联动，把推荐改成火红 Hot，把折扣移到档位名后，并整体上调字号。

### 改了什么

- `src/FastTranslation.App/Pages/PlanPage.xaml`：三张卡的档位名 18px、价格 38px、权益 13px、说明 12.5px；折扣徽标从第二行移到档位名后，字号 11.5；Pro 的「推荐」改成 `Hot`，底色用主题 `DangerBrush`（浅色 #DC2626 / 深色 #FF6B6B），文字用 `OnBrandTextBrush`，两套主题都保持对比度。
- `src/FastTranslation.App/Pages/PlanPage.xaml.cs`：加 `PriceCopy` 记录三档四价（月价、季价、月标价、季标价）；`SelectCycle` 调 `UpdatePrices`，月付显示 ¥6.9/月、季付显示 ¥20.7/季，副行回显另一周期与划线标价。
- 周期卡补 `AutomationProperties.Name` / `AutomationId`，UIA 探针能按名字定位；选中态仍靠边框和底色。
- `site/index.html` / `site/assets/site.css`：Pro 的「推荐」标签同步改成 `Hot`，新增 `--hot: #D92D20`。
- 没有改价格、订单金额或服务端逻辑。

## v143 交付前缺陷清扫：界面状态、失败提示、键盘可达与运维加固

### 为什么

备案下来前做了一次全仓审计（骨架 / 代码质量 / UX / 视觉）。问题不是新功能缺口，而是「用户会撞上但说不清」的一类：页面在请求期间白屏、按钮点完没有反馈、同一份设置在取消后仍然生效、网络异常直接逃出 UI 线程、深色主题焦点环几乎看不见；服务端则有三处会把内部状态或无效输入带进下一层；部署脚本的备份权限、恢复步骤与发码闸门也存在真实缺口。这一版按「能明确判定对错的直接修，涉及产品取舍的留清单」处理。

### 改了什么

**界面状态与交互**

- `MainWindow.xaml.cs`：启动时按工作区收缩窗口（只缩不放），1366×768 / 150% 缩放的笔记本上底部保存条不再落到屏幕外；侧栏账号行只显示邮箱，套餐名只保留在「套餐」行，避免长邮箱把状态挤成「（Lit…」。
- `MainWindow.xaml`：侧栏「套餐」行的 `PlanLabel` 跟随活动项 `Foreground`，蓝底上不再出现深灰字。
- `ReviewPage`：请求期间显示「正在加载…」；空队列与未登录分开给文案；卡片区套 `ScrollViewer`；评分请求期间切页/结束时用 `ReferenceEquals` 丢弃过期结果，异常落到页内提示。
- `PlanPage`：读取用量时进度环显示「…」而不是假的 0%；失败态显示「—」；兑换提示区分错误色与普通色，输入变化后复原。
- `NotesPage`：删除前用 `NoticeWindow.Confirm` 确认（原文截 24 字），评分/改分类/保存/删除都补了异常提示。
- `SettingsPage`：排除名单改为页面内副本，点「保存」才写回设置；「取消」和重新进入页面都会丢弃未保存改动。检查更新改为 `await` + 按钮禁用 + 完成后复原提示，不再永远停在「正在检查更新…」。
- `App.xaml`：默认按钮、主按钮、药丸按钮、链接按钮、复选框、开关补键盘焦点环；开关打开时滑块颜色跟随 `OnBrandTextBrush`。
- `App.xaml.cs`：写回失败给出「替换/插入没成功」提示；退出时释放更新协调器；引导页「稍后再说」写入 `FirstRunCompleted`，不再每次启动都弹。
- `SpeechWindow.xaml`：标题栏状态文字改为可省略的 `*` 列，长状态不再把关闭按钮挤出窗口；图标按钮与主界面/语音/文档下拉框补 `AutomationProperties.Name`。
- `NoticeWindow`：确认窗按 Esc 等同取消；纯告知窗支持回车关闭，确认窗刻意不设默认按钮，避免误按回车执行删除。
- `DocumentPage.xaml`：失败卡与错误卡补 `BorderThickness="1"`，危险色描边真正可见。
- 覆盖层 `OverlayWindows`：长原文改为内部滚动，去掉 220px 截断；加载指示改为虚线圆环；显示后按真实窗口高度重新夹取位置。

**文案与术语**

- 中文界面统一全角括号、逗号、冒号（`自动（中英互译）`、`API Key：已配置（本机加密保存）`、`热键注册失败（…），…`）；「生词本」统一为「单词本」，与侧栏、代码和规格一致。
- 托盘、账号页、语音窗等处的半角标点一并归一；第三方文件不动。

**健壮性**

- `TranslationService`：在途请求的取消源改为局部变量再原子交换，避免并发取消时把新请求的 token 一起取消。
- `WindowsSelectionCapture`：剪贴板恢复移入 `finally`，`SendCtrlC` 失败也先还原剪贴板。
- `WasapiLoopbackCapture`：`GetMixFormat` 的 CoTaskMem 在 `finally` 释放，设备被占用时不再每次漏一块。
- `SegmentTranslator`：编号解析改用 `TryParse`，并把「区间与重复编号」合并成一次校验，非法编号不再抛异常。
- `SpeechTranscriptService`：批量翻译前用 `TryGetValue` 取源句，缺句时跳过而不是 `KeyNotFoundException`。
- `SpeechTranslationCoordinator`：音频泵遇到意外异常时，若仍在推流则回调 `OnFatal`；行更新事件成对订阅/退订。

**服务端**

- `AuthEndpoints`：非 Development 且 SMTP 未配置时，注册发码返回 `503 mail_unavailable`；注册先查邮箱占用再消费验证码，失败注册不再白烧一次码。
- `VerificationMailSender`：未配置 SMTP 时只有 Development 把验证码写日志，生产只记「未发送」。
- `AccountStore.RegisterDevice`：空设备名不再覆盖已有名字（网关转发每次都传空串）。
- `DashScopeGateway`：调用方取消继续抛出，不记成上游 502。
- `GatewayRateLimiter`：每 1024 次请求清一次过期窗口，长期进程不再只增不减。
- `GatewayEndpoints.ReadMaxTokens`：只接受正整数，`0`/负数按未指定处理。

**部署、站点与仓库**

- `deploy/backup.sh`：`umask 077`、目录 700、备份前确认数据库存在、压缩前 `PRAGMA integrity_check` 失败即删并退出。
- `deploy/fasttranslation-logrotate` + `install.sh`：新增 `/var/log/ft-backup.log` 与 `ft-monitor.log` 的每周轮转（保留 8 份）。
- `deploy/go-live.sh`：`--skip-icp` 时不再执行「页面不得含占位符」的断言，改为告警；其余断言照跑。
- `deploy/README.md`：恢复步骤先删旧 `-wal`/`-shm`，并 `chmod 600` 恢复出的数据库；上传清单补 logrotate 文件。
- `admin/admin.css`：键盘焦点环从几乎不可见的 `--accent-soft` 改为实色 `--accent`。
- `.gitignore`：补 `*.db-journal`、`*.log`、`/data/`。
- `AGENTS.md`：更新过期的文件行数与最新分册名。

## v144 视觉与交互收口：页面骨架、卡片令牌、套餐键盘化、Toast 与浮层主题

### 为什么

v143 修了状态与文案，但视觉与交互上还有几处「能用但不整齐」：页面标题字号与边距每页一套，切页时标题会左右跳；内容卡圆角 10/12/16 混用、浅色下没有描边；套餐卡只能鼠标点，Tab 与方向键都选不了；提示条悬停时仍会倒计时消失；浮层是启动时创建的常驻窗口，切主题必须重启才变色。这一版按上一轮清单里的推荐逐项落地。

### 改了什么

**页面骨架**

- `App.xaml`：新增 `PagePadding = 24,20,24,24`，作为所有页面外壳的统一边距；`PageTitle` 保持 21px，`PageSub` 保持 12.5px。
- `NotesPage` / `ReviewPage`：标题从 17px 改为 `PageTitle`，补一行 `PageSub` 说明；标题与数量仍同一行，右侧刷新/去复习按钮不变；根 Grid 改用 `PagePadding`。
- `SpeechPage` / `AccountPage`：标题改用 `PageTitle` 并补副标题；`DocumentPage` / `PlanPage` / `SettingsPage` 的 `StackPanel` 边距改用 `PagePadding`。
- 首页保持工作区布局，不加页面标题——它是翻译输入区，不是内容页。

**卡片令牌**

- `Card` / `CardSurface`：圆角 16 → 12，补 1px `HairBrush` 描边。浅色下白卡不再只靠阴影分辨边界，深色下也不再用两种圆角。
- `NotesPage` / `ReviewPage` 的列表与详情卡、`AccountPage` 的内嵌渐变面板、`PlanPage` 的档位卡同步到 12；小控件（药丸、输入框、徽标）保持原圆角。

**套餐选择器键盘化**

- `PlanPage`：三张档位卡与月付/季付两项从 `Border + MouseLeftButtonUp` 改成 `RadioButton`，模板保留原视觉；新增 `TierCard` / `CycleCard` 样式，选中态、悬停态与键盘焦点环都由模板触发器画。
- `PlanPage.xaml.cs`：`Select` 改为设置 `IsChecked`；新增 `_selecting` 防回环，`Checked` 事件同时覆盖鼠标、空格和方向键三条路径。
- 每张卡补 `AutomationProperties.Name`（`Lite 套餐` / `Pro 套餐` / `Max 套餐`、`月付 30 天` / `季付 90 天`），UIA 能读到 RadioButton 的选中态。

**Toast**

- `ToastWindow`：鼠标进入时暂停倒计时，离开时按剩余时间继续；至少保留 250ms，避免离开瞬间就消失。位置仍固定主屏右下角——全局提示跟着鼠标跨屏跳反而会打断当前操作。

**浮层主题热切换**

- `OverlayWindows.cs` 的 `FtTheme`：画刷从「按色值缓存并 Freeze」改为「每个角色一个可变实例」；新增 `Refresh()` 按当前 `ThemePalette.Active` 就地改色。
- `SelectionToolbar` / `ResultCardWindow` / `ImageResultWindow` 各加 `RefreshTheme()`；`App.ApplyAppearance()` 在主题或强调色变化时调用，已显示的浮层立即换色，不必重启。

**顺带修掉的**

- 页面根 `ScrollViewer` 补 `FocusVisualStyle="{x:Null}"`：最小窗口尺寸截图里，套餐/设置页整块内容区会出现一圈黑色焦点框，根因是滚动视口拿到了键盘焦点；账号页 v111 已用同样写法规避。

## v148 修复运行中换肤打断标题栏刷新，并为主窗口增加平滑交叉淡出与系统主题监听

### 为什么

用户反馈「当换了个系统配色时，切换很生硬，而且上框也没切换过来还是深」（设置页客户区已变成浅色，顶部原生窗口标题栏却仍留在深色）：

- 根因：`v144` 在 `FtTheme` 中把可变 `SolidColorBrush` 直接写进 `Button` 的 `Style` `Setter`/`Trigger`。WPF 在控件首次使用并 `Seal()` `Style` 时会自动 `Freeze` 其中的 `Freezable`，导致首次运行中切换主题或强调色调用 `FtTheme.Refresh()` 就地修改 `Color` 时直接抛出 `InvalidOperationException`；异常打断 `App.ApplyAppearance()` 后，后面的循环重刷 `WindowChrome.SetDarkTitleBar(...)` 与设置页色块刷新被跳过，造成「客户区变了、上框没切过来」。
- 切换生硬：`App.ApplyAppearance()` 原先直接替换 `Application.Current.Resources` 里的画刷，整面窗口在一帧内硬跳变；同时缺少对 `Microsoft.Win32.SystemEvents.UserPreferenceChanged` 的监听，Windows 系统深浅色变化时选「跟随系统」不会自动跟随。
- 运行中重刷 DWM：`WindowChrome.SetDarkTitleBar` 只写了 `DwmSetWindowAttribute`，未在窗口可见时补发 `SetWindowPos(..., SWP_FRAMECHANGED)` 通知非客户区立即重算；主窗口从托盘重新显示时也没有同步一次标题栏状态。

### 改了什么

- `src/FastTranslation.Platform.Windows/OverlayWindows.cs` & `ImageResultWindow.cs`：将 `FtTheme` 改为维护一份共享 `ResourceDictionary`（`FtTheme.Resources`），存入已冻结画刷，通过 `FtTheme.Attach(Window)` 挂到浮层窗口并以 `Bind(...)` / `SetResourceReference` 走 `DynamicResource` 解析；`FtTheme.Refresh()` 改为整支替换变化后的冻结画刷，模板 `Style` `Seal()` 后切换主题不再抛异常。
- `src/FastTranslation.Platform.Windows/WindowChrome.cs`：`SetDarkTitleBar` 在窗口可见且属性设置成功时补发 `SetWindowPos(..., SWP_NOMOVE | SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE | SWP_FRAMECHANGED)` 通知 DWM 立即重算边框；`Apply(Window)` 增加 `IsVisibleChanged` 同步，主窗口从托盘隐藏期间若系统配色变化，重新 `Show()` 时也能立即同步标题栏。

- `src/FastTranslation.App/Pages/SettingsPage.xaml` & `SettingsPage.xaml.cs`：修正 `AccentChip` 外圈焦点环边距；为 `ReloadFromSettings()` 补齐 `_reloading` 防回环标记与 `PreviewThemeSetting` / `PreviewAccentSetting` / `RefreshAccentChips()`；`UpdateAccentChips()` 改为 `SetResourceReference` 引用 `BrandBrush` / `BrandFillBrush` / `BorderStrongBrush` / `SurfaceBrush`，不再缓存旧主题的静态画刷引用。
