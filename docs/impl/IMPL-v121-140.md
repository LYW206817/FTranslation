# Fast Translation 实施日志（IMPL）· v121–v140

## v121 运营后台静态单页与 Caddy `/admin` 路由

### 为什么

v120 补齐了管理接口，但运维只有 curl 入口：手机上看不了账号和用量，也没法点一下封号。2 核 2G 的 ECS 不适合再跑 Blazor Server 或 Node 构建链，所以选同域静态单页：没有构建步骤、没有第三方脚本、发布目录独立于官网；真正的授权仍是服务端 `X-Admin-Token` 与 `/api/v1/admin/*`，页面只负责展示和调用。

### 改了什么

- `admin/index.html` / `admin/admin.css` / `admin/admin.js`（新增）：令牌登录、概览、7/30 天用量与按日 SVG 柱状图、按来源表、账号前缀搜索 + 套餐筛选 + 分页、套餐变更（付费套餐天数必填，`0` = 永久、正数 = 相对天数；免费套餐发 `days=0` 清到期）、禁用/解禁、激活码生成/作废/分页、网关健康。
  - 页面不发送 `days=null`：免费账号的原到期时间是 null，留空改付费会变成永久，所以付费套餐的天数在页面层必填。
  - 令牌只放 `sessionStorage`，关闭标签即清除；所有服务端数据用 `textContent` 渲染，没有 `innerHTML`；禁用、改套餐、作废前都 `confirm`。
  - 页面无内联脚本/样式，Caddy 的 CSP 可以保持 `script-src 'self'; style-src 'self'`。
- `deploy/Caddyfile`：新增 `redir /admin /admin/ 308` 与 `handle_path /admin/*`，独立 root `/var/www/fasttranslation-admin`；响应加 `Cache-Control: no-store`、CSP、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`X-Robots-Tag: noindex`；Basic Auth 作为注释中的可选项，不默认启用。
- `deploy/install.sh`：把 `admin/` 复制到 `/var/www/fasttranslation-admin`；已填好的 `/etc/caddy/Caddyfile` 不含 `/admin` 路由时打印警告，不覆盖手改。
- `deploy/README.md`：文件表、首次部署/升级的 `cp` 列表补充 `admin/`，新增「运营后台」章节。
- `site/robots.txt`：加 `Disallow: /admin`。
- `AGENTS.md` / `README.md`：目录说明补 `admin/`。
- `docs/superpowers/specs/2026-11-10-monitoring-and-admin-design.md`：把「生成响应是码的唯一副本」改成「唯一一次批量返回，未兑换的码可在 `GET /codes` 里找回」，与现有列表接口和页面提示一致（规格漂移修正，不改接口行为）。

## v122 补差价升级：保留到期时间与已用字符

### 为什么

v121 的激活码兑换在升档时会保留已买天数，但剩余轻享天数也一并变成标准，等于免费升级；用户明确不接受。补差价升级必须是：运营在站外收款后只切换套餐，到期日不变，本月已用字符继续计入标准额度，不重置、也不叠加轻享剩余。

### 改了什么

- `admin/admin.js`：对生效中的轻享账号增加「升级标准」按钮，二次确认后调用现有 `POST /api/v1/admin/accounts/{email}/plan`，传 `{plan:"standard", days:null}`；成功后同时刷新账号表与概览卡片。
- 服务端不新增端点：`days=null` 原本就有「保留到期时间」语义；`usage_monthly` / `usage_daily` 不受 `SetPlan` 影响，所以标准额度从已用字符里扣。服务端不计算差价，收款仍是站外手动。
- `tests/FastTranslation.Server.Tests/AdminEndpointTests.cs`：新增 `Admin_upgrade_preserves_expiry_and_monthly_usage`，断言升级后套餐为标准、到期时间不变、已用字符不变、额度为 `StandardMonthlyChars - used`。
- `docs/superpowers/specs/2026-11-10-monitoring-and-admin-design.md`：补「补差价升级复用 plan 端点、不重置用量」的契约说明。

### 验证


- 隔离预览：`light.user@example.com`（编造账号），本月用量 12,000；升级前 light / 到期 2026-12-11 10:41:30 / 额度 50,000 / 剩余 38,000。
- 后台点「升级标准」后：standard / 到期时间不变 / 已用仍 12,000 / 额度 200,000 / 剩余 188,000；概览同步变为轻享 0、标准 1；无 JS 错误。

### 残留风险与未验证项

- 差价金额、剩余天数折算和收款凭据都靠运营手工计算；服务端只知道「换套餐并保留到期」，不校验金额。
- 通用「改套餐」仍可传正数天数并从今天重算到期时间；误用它做升级会缩短剩余天数。后台另给了专用升级按钮，但接口层没有禁止这种调用。
- 升级只对生效中的轻享账号显示；免费账号升轻享、或已过期账号续费仍走正常发码/改套餐，不适用「补差价」。
- 没有升级码；如果以后要让用户自助补差价，需要新增码类型并校验当前套餐，不能复用普通兑换码。

## v123 运营后台下拉菜单与窄屏溢出

### 为什么

v121 的账号表直接使用原生 `<select>`：收起状态还能用 CSS 统一，展开层却由浏览器/系统绘制，和页面的卡片、圆角、蓝色主色完全不是一套；用户点开「套餐」时最明显。另一个细节是窄屏下表格的 `min-width` 会把网格项和整页撑出视口（390px 宽度下 `bodyScrollWidth > innerWidth`）。

### 改了什么

- `admin/admin.js`：新增自定义下拉。
  - `enhanceSelect` 保留原生 `select` 作为状态容器（`.value`、`change` 事件与表单读取路径都不变），隐藏原生控件，改用按钮 + 共享菜单绘制；账号表每行动态套餐选择、账号筛选、激活码套餐与状态四处统一走同一套。
  - 菜单挂到 `body`、`position: fixed`；靠近视口底部时向上翻转，宽度按触发器宽度并限制在视口内；点击外部、滚动、缩放、Esc 都关闭。
  - 键盘可达：方向键展开并移动焦点，Home/End 跳转，Enter/Space 选中，Esc 关闭并把焦点还给触发器；菜单只创建一次，账号表翻页重建行时不会留下孤儿节点。
  - 长邮箱列改为最多 320px、省略号截断，完整地址放 `title`；避免长邮箱把「禁用/解禁」按钮挤出桌面视口。
- `admin/admin.css`：自定义触发器、菜单、选中项与焦点态；`.panel { min-width: 0 }`、`.table-wrap { max-width: 100% }` 防止表格的 `min-width` 撑出视口。
- 服务端、桌面端和 `/api/v1/admin/*` 契约均未改动；原生 select 的值仍由原有代码读取。

## v124 套餐改版：Lite / Pro / Max 与统一字符额度

### 为什么

原套餐只有两档付费（轻享 6.9 元 / 50,000 字符、标准 12.9 元 / 200,000 字符），额度是早期临时值。按 v109 的统一字符口径，语音 50 字符/秒，5 万字符只够讲约 17 分钟，付费档的“量”撑不起价格。2026-11-11 定为 Lite 6.9 元 / 88 万、Pro 11.9 元 / 188 万、Max 19.9 元 / 388 万字符，年付 69 / 119 / 199（按 10 个月）；三档都解锁单词本与四档复习，差别只在月度额度。

### 改了什么

- `server/FastTranslation.Server/Domain/Plan.cs`：新增 `PlanTier.Max = 3` 与 `MaxMonthlyChars = 3_880_000`，Light/Standard 额度改为 88 万 / 188 万；`ToWire` / `TryParse` 增加 `max`。**传输名 `light` / `standard` 保持不变**：存量令牌、激活码与 `users.plan` 的 1/2 都按这两个名字走，界面显示名才是 Lite / Pro，避免一次数据迁移。
- 服务端管理面：`AdminMetricsResponse` 增加 `maxUsers`，`AccountStore.ReadAccountMetrics` 增加 `SUM(plan = 3)`；后台卡片、筛选、激活码套餐与升级文案同步（升级按钮仍只对 Lite 显示，目标 `standard`）。
- 桌面端：`AccountProfile.PlanDisplay` 映射 Lite / Pro / Max；套餐页把“年付/月付”切换换成三张可选档位卡（¥6.9 / ¥11.9 / ¥19.9，卡内同时标年付价），登录后默认选中当前付费档，免费/未登录默认 Pro；订阅提示按所选档位回显。
- `site/`：套餐区从三张卡改成四张（免费 + Lite / Pro / Max），价格与额度对齐服务端；四卡变窄后额度与价格在 markup 里分两行，避免在“元 / 月”中间折断。
- 规格：账号计费规格 D7 / §1.1 / §6.1 / §10 更新；管理面规格的套餐过滤与升级文案补 `max`；README 与语音评估的显示名同步。README 的测试数一并从 787 修正为 915。

## v126 截图翻译按 OCR 原文自动判中英方向

### 为什么

设置里的目标语言选「自动(中英互译)」时，文字链路会按原文判方向（中文→英文、外文→中文），但截图翻译的 `ImageTranslationPolicy` 把 auto 固定解析成 `Chinese`。中文截图因此被要求「中文→中文」，qwen-mt-image 原样返回，用户看到的就是「截图翻译没变化」——v36 实现时只测了英文网页→中文，单向路径把问题藏住了。

### 改了什么

- `ImageTranslationPolicy.Resolve` 增加可选 `sampleText`（OCR 原文）：目标为 auto 时按文字链路同一条 `LanguagePolicy.DetectTarget` 规则判方向（中文占主导→English，其余→Chinese）；没有可信原文（OCR 失败/空串）仍回落 Chinese。显式目标语言完全不受影响。
- `ImageTranslationCoordinator`：OCR 先起跑；`TranslateImageAsync` 只在 auto 目标时 `await` OCR 拿原文，再发图片翻译请求。显式目标语言仍保持「译图与 OCR 并行」的快路径。代价是 auto 下译图晚 OCR 约 0.9s（v36 实测 B≈0.9s），但方向错会白花一次图片调用且用户看不到结果。
- 测试：QwenMt 图像测试 +6（中文样本→English、英文样本→Chinese、中英混排→Chinese、无字母文本→Chinese、空串→Chinese、显式目标不被样本推翻）。

### 验证

```
dotnet build FastTranslation.slnx -c Release → 0 警告 0 错误
dotnet test（Debug）→ Core 434 / Platform.Windows 107 / Providers 101 / Server 279 = 921 全绿
dotnet test -c Release --no-build → 同上 921 全绿
dotnet format style … IDE1006 → 本次改动文件无新增命中
```

- 本次不改界面布局，未重拍截图；真实中文截图的复测待做（目标语言需保持「自动(中英互译)」）。

### 残留风险与未验证项

- 方向只由 OCR 文本判定，OCR 失败或截图为纯图片/纯数字时回落 Chinese，中文截图仍可能原样返回；这是「没有原文就无法知道该译成什么」的固有限制。
- auto 模式下译图要等 OCR（约 0.9s）才发请求，总耗时从 max(A, B+C) 变成 B+max(A, C)；OCR 以后若变慢需要重新评估。
- 未用真实 qwen-mt-image 端点复测中文→英文（单测走本地假上游）；上线前建议用中文截图实测一次。

## v127 全量代码审查：修确定性缺陷、清死代码、补文档口径

### 为什么

功能连续堆了二十多个版本后做一次全量审查，重点看并发、生命周期、计费与文档漂移。下面每一条都先在代码里核实过；标「回归」的缺陷先写出了会失败的测试再修。

### 改了什么

服务端：
- **设备超限时记账抛外键错误（回归）**：`GatewayDevice` 在注册失败且找不到匿名设备行时返回 `Guid.Empty`，`usage_daily` 对 `devices` 有外键，上游已经翻译完、记账时 500，攻击者还能重复烧全站预算。改为回退到账号已有的设备；新增 `Chat_WithDeviceOverTheLimit_ChargesAnExistingDevice`（修复前必红）。
- `ServerDatabase` 连接串显式 `ForeignKeys = true`：账号注销依赖级联清理，数据完整性不押在 Microsoft.Data.Sqlite 的默认值上；注销测试加 `ClearAllPools()` 后断言设备行确实没了。
- 语音计费 `Bill` 加锁：上游泵的 usage 回调与 `finally` 的最短计费可能并发，原来会基于同一旧值重复记或丢增量。
- start 帧解析吞掉 `FormatException/InvalidOperationException`（`sampleRate: 1.5`、`type` 不是字符串）；`language_hints` 改用 `JsonSerializer.Serialize` 转义，客户端不能再往上游 JSON 里注入字段。
- 改密码先注册设备、再改密码并吊销令牌：设备满时整笔失败，不会出现「密码已改、全端已登出、却只回 400」。
- 后台改套餐拒绝负天数：原来负值落进 switch 兜底，把账号改成永久授权。
- 兑换加时改成一条 SQL 内读改写（`AccountStore.ExtendPlan`）：并发兑换不会各自基于旧到期时间覆盖对方，丢掉一张码的天数。
- `NoteStore` 的五处 SELECT 抄成一份 `SelectColumns` 常量，列顺序与 `ReadNote` 的序号绑在一起，避免漏改一处导致字段静默错位。

客户端 / Core：
- **第二实例覆盖设置（回归路径）**：第二次启动在读盘前 `Shutdown()`，但 WPF 仍会触发 `OnExit`，把默认 `AppSettings` 写回 `settings.json`。加 `_settingsLoaded`，没读过盘就不保存。
- **语音重复启动**：预检的网络往返期间 `_speechCoordinator` 还是 null，连按热键会再开一条会话，前一条 WS 继续按秒计费。加 `_speechStarting` 闸门。
- **语音停止/释放竞态**：`StopAsync` 与 `DisposeAsync` 并发，Dispose 释放传输层 CTS/WebSocket 后 Stop 的 `CloseAsync`/`finally` 再碰就抛 `ObjectDisposedException`，`Observe` 把它当会话失败显示红字。改为 `StopThenDisposeAsync` 串行执行；收尾失败不再拆掉已经开始的新会话。
- **语音泵重入**：100ms 定时器在弱网时可能起出两条并发循环，`ClientWebSocket` 只允许一个发送在途，后到的块抛异常后丢失。加 `_pumpBusy` 闸门。
- **语音用量少报**：服务端每条连接各自从 0 计费，重连后 `max()` 会停在断线前的值。断线时把当前累计存成 `_usageBase`，新会话的 usage 叠加它。
- **字幕翻译不停**：结束/暂停/关浮窗后，防抖里与队列里的翻译仍按用户额度继续发请求。`SpeechTranscriptService` 加 `_lifetime` CTS，`Dispose` 取消；`EndSpeechSession` 真正调用它。
- 语音浮窗点 X 时先 `EndSpeechSession` 再清 `_speechWindow`，且删掉空订阅的 `ClearRequested`（清空按钮本来就直接清 `_lines`）。
- 账号变化回调统一切回 UI `Dispatcher`：文档链路在后台线程刷新令牌会触发 `Changed`，直接改侧边栏会抛异常并被吞掉，表现为额度不刷新。
- 结果卡提示计时器：新加载态/结果态先停 `_noticeTimer` 并恢复复制按钮，否则「已复制」提示 2.5 秒后会把刚显示的结果藏掉。
- 截图结果窗：译图晚到时不再把已经点过的「已保存」重新点亮。
- 托盘钩子失败提示挪到 `_tray.Show()` 之后：原来气球在托盘图标创建前发出，静默丢失。
- 文档翻译：每 10 秒把已完成单元落一次断点；有失败段时保留断点，「重试」只补译失败段，不再把已扣额度的段全部重译；预检改为按断点回填后真正要译的字符数；进度分母改为可译段并加回已译段，续译到得了 100%；单段超过 5000 字符在开跑前拒绝（`DocumentLimits.CheckSegments`），不再三轮重试后整段写回「未翻译」。
- 显式目标语言（如日语）+ 源语言 auto 时，请求源语言改为 `auto`，不再硬填「中文/英文里的另一种」；自动目标仍按中英互译判向。
- `settings.json` 改为临时文件 + `File.Move(overwrite)` 原子写；半截 JSON 不会再被静默当默认值后覆盖用户全部配置。
- 账号接口 `account_missing` 映射为 `Unauthorized`：服务端清库后本地会清死会话并提示重新登录，而不是一直「服务器出错了」。
- 清死代码：`CoordinatorState`、`TranslationService.RequestCompleted`、`Settings.ClipboardPollMs/CaptureOnClickOnly`、`NotesBaseUrl`、`MainPage.InputBox.FocusInput`、`ClipboardService` 的实例字段与 `CaptureViaCopy`、`LowLevelMouseHook._ownProcessName`、`IID_IMMDeviceEnumerator`、`ResultCardWindow.Dismissed`、`ImageResultWindow.ShowResult(byte[], string)` 旧重载、`SpeechWindow.ClearRequested`、`SegmentTranslator` 里只透传不使用的 `progress` 参数。
