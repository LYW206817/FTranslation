# Fast Translation 实施日志（IMPL）· v121–v140

## v121 运营后台静态单页与 Caddy `/admin` 路由

### 为什么

v120 补齐了管理接口，但运维只有 curl 入口：手机上看不了账号和用量，也没法点一下封号。2 核 2G 的 ECS 不适合再跑 Blazor Server 或 Node 构建链，所以选同域静态单页：没有构建步骤、没有第三方脚本、发布目录独立于官网；真正的授权仍是服务端 `X-Admin-Token` 与 `/api/v1/admin/*`，页面只负责展示和调用。

### 改了什么

- `admin/index.html` / `admin/admin.css` / `admin/admin.js`（新增）：令牌登录、概览、7/30 天用量与按日 SVG 柱状图、按来源表、账号前缀搜索 + 套餐筛选 + 分页、套餐变更（付费套餐天数必填，`0` = 永久、正数 = 相对天数；免费套餐发 `days=0` 清到期）、禁用/解禁、激活码生成/作废/分页、网关健康。
  - 页面不发送 `days=null`：免费账号的原到期时间是 null，留空改付费会变成永久，所以付费套餐的天数在页面层必填。
  - 令牌只放 `sessionStorage`，关闭标签即清除；所有服务端数据用 `textContent` 渲染，没有 `innerHTML`；禁用、改套餐、作废前都 `confirm`。
  - 页面无内联脚本/样式，Caddy 的 CSP 可以保持 `script-src 'self'; style-src 'self'`。
- `deploy/Caddyfile`：新增 `redir /admin /admin/ 308` 与 `handle_path /admin/*`，独立 root `/var/www/fasttranslation-admin`；响应加 `Cache-Control: no-store`、CSP、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`X-Robots-Tag: noindex`；Basic Auth 作为注释中的可选项，不默认启用。
- `deploy/install.sh`：把 `admin/` 复制到 `/var/www/fasttranslation-admin`；已填好的 `/etc/caddy/Caddyfile` 不含 `/admin` 路由时打印警告，不覆盖手改。
- `deploy/README.md`：文件表、首次部署/升级的 `cp` 列表补充 `admin/`，新增「运营后台」章节。
- `site/robots.txt`：加 `Disallow: /admin`。
- `AGENTS.md` / `README.md`：目录说明补 `admin/`。
- `docs/superpowers/specs/2026-11-10-monitoring-and-admin-design.md`：把「生成响应是码的唯一副本」改成「唯一一次批量返回，未兑换的码可在 `GET /codes` 里找回」，与现有列表接口和页面提示一致（规格漂移修正，不改接口行为）。

### 残留风险与未验证项

- 本机没有 `caddy`，`caddy validate` 未跑。Caddyfile 只做了人工检查；部署时 `install.sh` 会执行 validate，失败会挡住。
- `install.sh` 的 `admin/` 复制与「Caddyfile 缺 `/admin` 路由」警告没有在服务器实跑。首次升级到本版时，若线上 `/etc/caddy/Caddyfile` 已去掉占位符，需要把 `redir /admin` 与 `handle_path /admin/*` 合并进去，或用 `FT_FORCE_CADDYFILE=1` 重新铺模板（会覆盖手改）。
- 管理页固定浅色、没有 i18n；手机上表格靠横向滚动。
- 管理令牌仍是共享密钥，没有多操作员、审计表与二次确认口令；与 v120 相同，后续要多人运维时再补。
- 浏览器验证是在本机 Chromium 上做的，未在 iOS/Android 实机验证布局。
