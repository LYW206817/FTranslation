## v182 — 修复 Workbench 与 Tailscale 的 100.64 网段冲突(2026-11-18)

**现象**:用户从阿里云控制台「实例登录」(Workbench) 连接 `root@172.28.26.100:22` 恒定失败,提示检查安全组白名单 `100.104.0.0/16`;而 Tailscale(`ssh root@100.81.197.32`)一切正常。

**诊断**

| 检查 | 结果 |
|---|---|
| 安全组 | 实例只绑 1 个组,`22 → 100.104.0.0/16` 规则存在 |
| ufw | `22/tcp ALLOW Anywhere`,无对 100.104 的拦截记录 |
| sshd | 监听 `0.0.0.0:22`,对 `100.104.0.0/16` 允许密码与 root 登录 |
| 云助手 | `aliyun.service` active |
| 抓包(150 秒) | 抓到 `100.104.113.243 → 172.28.26.100:22` 的 4 个 SYN,**没有 SYN-ACK** |
| INPUT 链 | 第一条是 Tailscale 的 `ts-input`,其末行 `DROP !tailscale0 100.64.0.0/10` |

**根因**:阿里云 Workbench 的来源 `100.104.x.x` 属于 `100.64.0.0/10`(CGNAT 段),被 `ts-input` 的 DROP 规则在 ufw 之前丢掉。tcpdump 在 netfilter 之前抓包,所以能看到 SYN 入站却看不到任何回应。

**修复**

- 新增 `deploy/ft-tailscale-workbench-allow.sh`:幂等地在 `ts-input` 顶部插入 `100.104.0.0/16 → ACCEPT`,链未建好时每秒重试最多 30 次。
- 新增 `deploy/tailscaled-workbench.conf`:drop-in,`ExecStartPost` 执行上述脚本——`tailscaled` 每次启动都会重建 `ts-input`,只手工加一次不够。
- `deploy/install.sh` 安装上述两个文件并 `daemon-reload`;`deploy/README.md` 的 Tailscale 小节补充成因与验证命令。

**验证**

- 用户在控制台重新登录成功。
- `iptables -L ts-input -n` 第一条为 `100.104.0.0/16 ACCEPT`。
- `systemctl show tailscaled -p DropInPaths` 包含 `workbench.conf`。

**残留**

- 未重启 `tailscaled` 验证规则自动恢复(重启会切断当前唯一的 SSH 通道);下次自然重启时生效,若不生效按脚本手补。
