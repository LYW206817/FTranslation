## v201 — 限制 DOCX 展开量，保留原剪贴板（2026-11-21）

- `DocxDocumentTranslator` 先限制条目数量与展开量，读取时核对实际字节。输出改用临时文件流式重建，成功后再替换已有文件。
- `ClipboardService` 在纯文本剪贴板才暂存译文，进入粘贴和恢复前验证所有权。非文本或忙时使用 Unicode 输入，输入期间切窗即停止。项目内取词与写回共用操作锁。
- 验证：DOCX 取消写回的新增用例修前红、修后绿。两配置文档与 Windows 平台用例均全绿。此次没有覆盖真实外部编辑器中的写回竞态和剪贴板多格式实机矩阵。

## v203 — HTTP 网关结算、重试与成本对账（2026-11-21）

- 文本、图片和 OCR 向上游发送前登记成本预留。同一次操作的客户端重试沿用标识。成功结果与个人用量、匿名日账同时提交。确定未发送或上游明确拒绝时释放预留，结果不明时转待核对。服务重启及运行中超过截止期限的发送都能进入对账。
- 待核对估算按发起日计入预算占用。后台及监控分别显示已结算与待核对。登记供应商确认的金额只影响匿名成本，重复提交同金额不累加。已完成明细有限期清理，未确认账目留存。
- 验证使用旧 schema 与三桶合成流水、模拟供应商响应及可拨动时钟。已验证迁移保存三桶合计，监控把当日已超时发送计入待核对，结果不明的动作不会因重试遇到 429 再转到直连。后台概览的取样在用量卡，见 `publish/security-v203-qa/admin-usage-desktop.png` 和 `admin-usage-mobile.png`。
- 真实供应商账单及历史差额待核对。部署时服务端与监控脚本一起更新。未部署生产。
